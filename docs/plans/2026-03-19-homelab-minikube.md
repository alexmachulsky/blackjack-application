# Home Lab Minikube Setup — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make the project a clean home lab setup — private GHCR images pulled via Sealed Secrets, Minikube-accurate manifests, and fully rewritten infra docs.

**Architecture:** CI (GitHub Actions) builds and pushes images to private GHCR as before. Minikube pulls those private images using a `ghcr-pull-secret` Kubernetes `docker-registry` secret that is stored encrypted in the repo as a `SealedSecret`, decrypted at runtime by the sealed-secrets controller running in Minikube. App secrets (DB_PASSWORD, SECRET_KEY) remain injected via `deploy.sh` env vars unchanged.

**Tech Stack:** Kubernetes, Sealed Secrets controller, kubeseal CLI, bash, kubectl

---

## Pre-conditions

The operator must complete these one-time manual steps **before** running `deploy.sh` for the first time on a fresh cluster. These are not automated — document them only (Task 5 covers the README).

1. `minikube start --driver=docker --cpus=2 --memory=4g`
2. `minikube addons enable metrics-server`
3. Install sealed-secrets controller:
   ```bash
   kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/latest/download/controller.yaml
   ```
4. Install kubeseal CLI: `brew install kubeseal`
5. Create a GitHub PAT with `read:packages` scope at https://github.com/settings/tokens
6. Set GHCR packages to **private** in GitHub → your profile → Packages → Package settings
7. Generate and commit the sealed secret (see Task 1)

### Task 1: Generate the SealedSecret for GHCR pull auth

This is a **one-time manual step** performed by the operator. The plan documents the exact command; the output file is committed to the repo.

**Files:**
- Create: `infra/k8s/ghcr-pull-secret.yaml` (generated by kubeseal, not hand-written)

**Step 1: Ensure the namespace exists first**

```bash
kubectl apply -f infra/k8s/namespace.yaml
```

Expected: `namespace/blackjack created` or `namespace/blackjack unchanged`

**Step 2: Generate and seal the secret**

Replace `<YOUR_PAT>` with the GitHub PAT (read:packages scope):

```bash
kubectl create secret docker-registry ghcr-pull-secret \
  --docker-server=ghcr.io \
  --docker-username=alexmachulsky \
  --docker-password=<YOUR_PAT> \
  --namespace=blackjack \
  --dry-run=client -o yaml \
  | kubeseal -o yaml > infra/k8s/ghcr-pull-secret.yaml
```

Expected: file written at `infra/k8s/ghcr-pull-secret.yaml`, containing a `SealedSecret` resource with `kind: SealedSecret` and an `encryptedData` block. The PAT is not visible in plain text anywhere.

**Step 3: Verify the file looks correct**

```bash
grep "kind:" infra/k8s/ghcr-pull-secret.yaml
grep "encryptedData" infra/k8s/ghcr-pull-secret.yaml
```

Expected output:
```
kind: SealedSecret
  encryptedData:
```

**Step 4: Commit**

```bash
git add infra/k8s/ghcr-pull-secret.yaml
git commit -m "feat: add sealed GHCR pull secret for private image access"
```

## One-time cluster setup

Run these once per fresh Minikube cluster. The cluster survives `minikube stop`/`start` — only `minikube delete` requires repeating these steps.

### 1. Start Minikube

```bash
minikube start --driver=docker --cpus=2 --memory=4g
minikube addons enable metrics-server
```

### 2. Install the sealed-secrets controller

```bash
kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/latest/download/controller.yaml
# Wait ~30s for it to be ready
kubectl rollout status deployment/sealed-secrets-controller -n kube-system --timeout=60s
```

### 3. Generate the GHCR pull secret

Create a GitHub Personal Access Token with `read:packages` scope at https://github.com/settings/tokens.

Then create the namespace and seal the secret:

```bash
kubectl apply -f infra/k8s/namespace.yaml

kubectl create secret docker-registry ghcr-pull-secret \
  --docker-server=ghcr.io \
  --docker-username=alexmachulsky \
  --docker-password=<YOUR_PAT> \
  --namespace=blackjack \
  --dry-run=client -o yaml \
  | kubeseal -o yaml > infra/k8s/ghcr-pull-secret.yaml

git add infra/k8s/ghcr-pull-secret.yaml
git commit -m "feat: add sealed GHCR pull secret"
git push
```

The PAT is encrypted inside the file — it is safe to commit.

### 4. Set GHCR packages to private

In GitHub: Profile → Packages → select `blackjack-application/backend` → Package settings → Change visibility → Private. Repeat for `frontend`.

## Deploying

```bash
export DB_PASSWORD=yourpassword
export SECRET_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")

./infra/k8s/deploy.sh
```

The script will:
1. Check Minikube is running and sealed-secrets controller exists
2. Create the `blackjack` namespace and app secrets
3. Apply the GHCR pull secret (decrypted by the controller)
4. Deploy PostgreSQL, backend, frontend
5. Apply HPA (if metrics-server is enabled) and PDB

Access the app: `open http://$(minikube ip):30080`

## Day-to-day operations

```bash
# Re-deploy after CI pushes a new image
git pull origin deploy/staging   # get updated image tags from CI
./infra/k8s/deploy.sh

# Watch pods
kubectl get pods -n blackjack -w

# Backend logs
kubectl logs -n blackjack -l app=backend -f

# Postgres logs
kubectl logs -n blackjack -l app=postgres -f

# Stop the cluster (state is preserved)
minikube stop

# Start the cluster again
minikube start
```
